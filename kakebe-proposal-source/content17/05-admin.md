# 5. The Admin Control Panel

*A role-based workspace where the Foundation's own people publish, review, translate and report, with every change recorded and reversible.*

The admin is where the platform stays alive after launch, so it is built for the Foundation's staff and volunteers, not for developers: one consistent layout, a live notification bell for every new submission, and every content type edited through the same simple forms.

## Six roles

| Role | Typical person | Can do |
|---|---|---|
| **Super admin / Admin** | Platform owner, operations lead | Everything, including users, settings and backups |
| **Editor** | Communications staff | Create and publish news, pages, history, heritage, events, programmes |
| **Moderator** | Language experts, community managers | Review contributions, word suggestions, comments and messages |
| **Clan leader** | Verified leader of one clan | Edit their own clan only; changes are reviewed, never self-published |
| **Contributor** | Any registered member | No admin access; submits from the website or app |

## What can be managed

| Group | Managed items (30 content types plus bespoke screens) |
|---|---|
| **Culture and language** | Dictionary, proverbs, lessons, clans (bulk add and CSV import), districts, notable Langos, history chapters, timeline, glossary, heritage, species, 360 tours |
| **Content and media** | News, events, programmes, media, documents, partners |
| **Community and moderation** | Contributions, word and proverb suggestions, comments, messages, applications, professionals, subscribers |
| **Finance and assistant** | Donations (confirm, export), programme progress; assistant knowledge base and flagged answers |
| **System** | Users and roles, branding, **Translations** (the Leb Lango interface, entered by experts, never machine-translated), notifications, audit log, backup, export |

## The moderation workspace

This is the screen that protects the Foundation's credibility. A reviewer opens a contribution with its photos, audio and map pin, adds a note the contributor sees, corrects it, then approves, publishes, returns or rejects it. Each action notifies the contributor in the app and by push, awards points, and an approved item can be added to the archive as a permanent record.

## Safe by design

Version history with restore; an audit log of who did what and when; forced password change at first sign-in; login throttling and rate limits; CSV and JSON export and a full database backup on demand. After handover the Foundation can run all of this itself; Kakebe is needed only for new features, security updates and infrastructure.
